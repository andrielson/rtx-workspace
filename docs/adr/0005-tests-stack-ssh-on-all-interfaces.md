# Publish the Tests stack's SSH surface on every interface

The Tests stack published its throwaway SSH port bound to the host's loopback (`127.0.0.1`) — fine for a suite run on the host, but the suite must also run from inside a workspace (the pre-push hook runs it wherever the developer pushes from), and a containerized runner cannot reach the host's loopback: its `127.0.0.1` is its own network namespace, so every SSH-surface test failed with connection refused while the workspace itself was healthy. Decision: publish on `0.0.0.0` (every interface) and let the suite pick the target — `127.0.0.1` on a plain host, the default route's gateway address (parsed from `/proc/net/route`, with `/.dockerenv` marking a containerized runner) when inside a container, the one host address a container can use to reach a published port. Exposure stays bounded: the port is random and lives only as long as the suite, the only key that can log in is the throwaway pair generated per run, and the container dies in the suite's teardown. Rejected alternative: parameterizing the bind back to loopback through an env var — it would keep host runs marginally tighter but adds a second configuration axis every `up` in the suite must keep consistent, for a runner class (plain host) where `0.0.0.0` changes nothing observable.
