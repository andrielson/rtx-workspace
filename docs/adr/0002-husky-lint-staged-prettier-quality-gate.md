# Adopt Husky, lint-staged and Prettier as the commit-time quality gate

The hand-rolled hook system (`preinstall` setting `core.hooksPath`, staged-file filtering re-implemented inside the hook) worked, but every new gate meant maintaining that machinery by hand, and formatting coverage was split: Biome owned the TS family, shell depended on a host-installed `shfmt`, and markdown/yaml/Dockerfile had no formatter at all. We adopt the standard stack, adapted to the repo's conventions: Husky as the hook runner — activated by the `prepare` lifecycle script, so no manual git config and a fresh clone needs zero setup; lint-staged as the staged-file fixer manager (`.lintstagedrc.json`); and a strict two-formatter split — Biome keeps ts/tsx/js/jsx/json/jsonc, Prettier (with prettier-plugin-sh, which embeds shfmt's engine) takes markdown, yaml, shell and Dockerfile, with `.prettierignore` enforcing the boundary so the two never own the same file. Blocking verifiers (ShellCheck, Compose validation, typecheck) deliberately stay in the pre-commit hook script instead of the lint-staged config, because lint-staged runs glob groups concurrently and a checker racing a writer on the same file is not deterministic; the Docker test suite is too slow to gate every commit, so it moved to a `pre-push` hook (once per push) behind a new `test` script. Hooks stay TypeScript executed by Bun — type-checked and linted like the rest of the repo (`tsconfig.json` and `biome.json` include `.husky/` explicitly, since `**` skips dot-directories): husky runs hook files through `sh`, so each extensionless hook is a minimal shell shim delegating to its sibling `.ts` implementation. Accepted losses: the host `shfmt` prerequisite disappears along with its `format:sh` scripts (the shfmt policy migrated from `.editorconfig` into `.prettierrc` as plugin options), and shfmt's `simplify` has no prettier-plugin-sh equivalent. Escape hatches remain: `git commit --no-verify` and `HUSKY=0`. The workspace image keeps its own shfmt and ShellCheck — they serve workspace users, not this repo's pipeline.

> **Amended 2026-09-12:** the `test` script was removed as redundant (Bun's test runner is built in — `bun test` needs no script), and the pre-push gate was narrowed to the `Dockerfile` test block (`bun test --only-failures --test-name-pattern Dockerfile`): the `user-install` half depends on real vendor endpoints, and intermittent network failures made a full-suite push gate unreliable. The full suite remains a manual `bun test` run.
