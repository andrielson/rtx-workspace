# Per-worktree Tests stack identity for parallel suite runs

The Tests stack identified itself through Docker-global constants — the project name, a `container_name`, two `image:` tags, and three one-off `run --name` containers hardcoded in the test file — so two checkouts (git worktrees, concurrent agent sessions) sharing one Docker daemon collided, and in the worst way defensively: a run's opening `down`/`docker rm` teardown destroyed the other run's live containers mid-test, and every `bun test` overwrote the hand-built local `rtx-workspace:latest` (the same shadowing the nginx service's dedicated tag existed to avoid). The stack now identifies per worktree: the suite resolves `rtx-workspace-tests-<8 hex>` (32 random bits, `crypto.getRandomValues`) from `tests/.env` — compose's own project-directory `.env`, holding exactly `COMPOSE_PROJECT_NAME=<project>` — generating and self-healing the record when it is missing or malformed, and passing `--project-name` explicitly anyway, so a stray exported `COMPOSE_PROJECT_NAME` in a shell cannot hijack the suite (the flag outranks both shell and file). With the identity per worktree, the fixed names are gone rather than suffixed: no `name:`, `container_name:` or `hostname:` in the compose file, no `image:` tags (builds land on compose's project-scoped defaults, verified as `<project>-<service>` on Compose 5.5.1), and the test file resolves what it needs at runtime — the workspace container's name through `compose ps --quiet` plus `docker inspect`, the built image by ID from the container running it — instead of assuming a naming scheme. Because compose loads that `.env` itself, manual flagless invocations (`docker compose --file tests/docker-compose.yml logs workspace`) aim at the live per-worktree project with no ceremony. The record is an identity, not a lock: it is never deleted, so the next run in the worktree reuses it and its defensive teardown cleans a crashed predecessor's leftovers; two concurrent runs in the _same_ worktree still collide (out of scope — the goal is one run per worktree), and deleting the worktree orphans its project until a manual `down`. Rejected alternatives: a fresh suffix per run — leaves a SIGKILLed run's project nameless and uncleanable; a deterministic hash of the worktree path — opaque to humans and silently changes identity when a worktree moves; a custom-named record file — needs its own ignore entry plus `--project-name "$(cat …)"` ceremony that compose's `.env` mechanism makes unnecessary; keeping fixed names with `${…}` interpolation in the compose file — turns every manual invocation without the variable set into a differently-named project. Resource contention between parallel runs (disk, `--pull` bandwidth, CPU) is deliberately unmitigated.
