# Bake the Bootstrap script into a built nginx image for the Tests stack

The Tests stack inherited the Base compose's nginx, which serves the Bootstrap script by bind-mounting `src/user-install.sh` into the Web root — but bind-mount sources are resolved by the Docker daemon against the host filesystem, and when the suite runs from inside a workspace the repo lives in the container's `/nix` named volume, invisible at that host path. Docker silently created an empty directory there and mounted it over the Web root, so every healthcheck `wget` got a 403 (`directory index of "/usr/share/nginx/html/user-install.sh/" is forbidden`) and `up --wait` aborted the `user-install` block after the full ~3-minute healthcheck budget — a blocker that sat hidden behind the earlier docker-socket permission bug, which had always failed the suite first. Decision: the Tests stack's nginx builds its own image (`tests/Dockerfile.nginx` — `FROM nginx:alpine` plus one `COPY`) with the repository root as build context, because a build context, unlike a bind, always travels client-side to the daemon — the same reason the workspace image build already worked from inside. Three guards make it safe: a root `.dockerignore` allowlisting exactly `src/user-install.sh` keeps the context at kilobytes (`node_modules` alone is 192M), `volumes: !override []` drops the inherited bind, and the dedicated `rtx-workspace-tests-nginx:latest` tag keeps the build from shadowing the official `nginx:alpine` the Base declares. Rejected alternatives: a symlink to the script inside `tests/` (COPY never follows symlinks resolving outside the context — the client tar carries the link entry, not the target's content), and moving the build into the Base compose (it would change the Prod stack's serving mechanism: every `user-install.sh` edit would start requiring an image rebuild, for a bind that works fine where Prod is actually driven from — the host). Accepted consequence: the Tests stack serves the Bootstrap script by a different mechanism than Prod, tolerable because the suite verifies the workspace's first-boot flow, not nginx's serving mechanism, and the script is the same file from the same commit either way; the suite rebuilds the image on every run (`build --pull`), so edits to the Bootstrap script need no extra step.

> **Amended 2026-09-13:** the baked-image decision stands; the context does not. The Base compose referenced here no longer exists, and the Tests stack's nginx now builds from `src/` itself — through the `tests/src` symlink — so the root `.dockerignore` allowlist was deleted along with its context, `src/.dockerignore` un-ignores `user-install.sh` instead, and the COPY reads `user-install.sh` from the context root. The rejected "move into the Base compose" alternative is moot (no Base compose). See [ADR 0007](0007-standalone-tests-compose-symlink-context.md).
