# Standalone Tests compose file building both images through a tracked symlink

The repository's product is the workspace image (`src/Dockerfile` and its runtime), not a compose stack, so the extends layering (ADR 0001) and its consumers went away: the Base compose (`src/docker-compose.yml`) and the Prod overlay (root `docker-compose.yml`) are deleted, `tests/docker-compose.yml` stands alone with every service declared in full, and `lint:compose` validates that one file. Both of its builds now share a single context: each declares `context: src`, and a tracked symlink `tests/src` → `../src` resolves to the real `src/` — the same tree the old Base's `build: .` uploaded. The symlink is deliberately the context _path_ and never an entry inside a context: `COPY` does not follow symlinks that escape the context (the reason ADR 0004 rejected a link to the script), but a context path is resolved client-side before the tree is walked (the buildx local mount resolves the root link; docker/cli's classic builder evaluates it explicitly — verified empirically against Compose 5.5.1, buildx 0.35 and engine 29.8). nginx keeps its Dockerfile in `tests/`, now outside the context (`dockerfile: ../Dockerfile.nginx`); every builder supports that through the Dockerfile's separate transfer — buildx mounts its directory as its own local mount, the classic builder injects it into the context tar. Consequences: the root `.dockerignore` allowlist is deleted (nothing builds from the repository root anymore); `src/.dockerignore` un-ignores `user-install.sh` so the nginx image's `COPY user-install.sh` finds it, and the script now also rides along in the workspace image's context tar — but the workspace Dockerfile never copies it, so that image is unchanged; and checkouts without symlink support (Windows without developer mode, some archive tools) materialize `tests/src` as a text file containing `../src`, breaking both builds there until the link is recreated. Running a workspace is out of the repository's scope now — the README documents building the image, and the entrypoint's first boot still expects an nginx sibling serving the Bootstrap script. Rejected alternatives: plain relative contexts (`context: ../src`) — mechanically equivalent, resolving to the same tree; the tracked symlink was preferred for keeping the compose file's paths local to `tests/` and for following the repo's tracked-symlink precedent (`CLAUDE.md`, the worktrees links); copying `src/` into `tests/` at test time — staleness machinery, and manual builds break before the first copy; and keeping nginx on the repository-root context with the root `.dockerignore` allowlist (ADR 0004's original arrangement) — superseded by moving both builds onto the symlink, which deletes the second ignore file and the `COPY src/user-install.sh` path juggling.
